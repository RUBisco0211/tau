# Tau 的 Context Compaction 机制

这份笔记讲 Tau 如何压缩（compact）上下文：当对话太长时，把较早的消息交给模型压成一份摘要，替换掉旧消息，让后续请求只带"摘要 + 最近的少量消息"。

## 核心思想

一句话：**旧消息 → 模型摘要 → 摘要替换旧消息 → 保留最近的消息**。

- 会话历史文件始终保留完整记录，不做任何删除（append-only）。
- 压缩只影响"当前发给模型的消息列表"（active context）。
- 压缩后发给模型的大致是：`[摘要, 最近保留的消息, ...]`。

## 基本流程

```text
                      ┌─────────────────────────────┐
                      │  1. 触发（三选一）            │
                      │   · 手动 /compact            │
                      │   · 自动：token 估算超阈值    │
                      │   · 溢出：模型报 context 溢出  │
                      └─────────────┬───────────────┘
                                    v
                      ┌─────────────────────────────┐
                      │  2. 决定压缩哪些消息          │
                      │   · 手动：全部旧消息          │
                      │   · 自动/溢出：保留最近 ~20k  │
                      │     tokens，只压更早的       │
                      └─────────────┬───────────────┘
                                    v
                      ┌─────────────────────────────┐
                      │  3. 调模型生成结构化摘要      │
                      │   （独立请求，不带工具）      │
                      └─────────────┬───────────────┘
                                    v
                      ┌─────────────────────────────┐
                      │  4. 写入会话树               │
                      │   一条 CompactionEntry 记录  │
                      │   "摘要替换了哪些旧消息"      │
                      └─────────────┬───────────────┘
                                    v
                      ┌─────────────────────────────┐
                      │  5. 重建 active context      │
                      │   旧消息 → 摘要 + 保留的最近   │
                      │   消息，替换内存里的消息列表   │
                      └─────────────────────────────┘
```

## 各步骤细节

### 1. 触发

| 方式 | 说明 |
|---|---|
| 手动 | 用户输入 `/compact`，压缩全部上下文（可附指令影响摘要重点） |
| 自动 | 每轮对话前后检查 token 估算值，超过阈值（默认 ≈ 窗口 − 16k）就压缩 |
| 溢出 | 模型报"context too long"类错误时，压缩后自动重试这一轮 |

### 2. 决定压缩范围：切点选择

- **手动**：压缩全部消息，不选切点。
- **自动 / 溢出**：只压缩较早的消息，保留最近约 20k tokens。切点选择分两步（核心代码在 `session.py` 的 `_recent_preserving_compaction_plan()` 与 `_first_recent_context_index()`）：

**第一步：从后往前数 token，找候选切点**

```text
从最后一条消息往前，逐条累加估算 token（4 字符 ≈ 1 token）
第一次累计达到 20k 的那条消息 = 候选切点（"最近尾巴"最早的一条）
若整个上下文凑不满 20k → 不压缩（上下文本身很小）
```

**第二步：按消息角色修正切点**（避免把一轮问答拦腰截断）

```text
候选是 user 提问 → 保留区从这条提问开始（它之前的全压掉）
候选是 assistant / toolResult →
    往后找下一条 user 提问，保留区从它开始（把半截回合一并压掉）
    后面没有 user 了 → 保留区从切点起第一个非 toolResult 消息开始（即最近的回答）
```

**示例**（一条典型消息流，阈值恰好越过在 index 4）：

```text
0 user        "fix the bug"
1 assistant   [tool_calls]
2 toolResult
3 assistant   "I fixed it"
4 user        "now test it"     ← 候选切点（user，index > 0）
5 assistant   [tool_calls]
6 toolResult
7 assistant   "tests pass"

压缩 [0..3]（交给模型做摘要）
保留 [4..7]（从新提问开始原样保留）
```

若阈值越过在 index 3（assistant）：向后找到下一条 user（4），同样压缩 `[0..3]`、保留 `[4..7]`，半截回答被压掉，保留区从干净的新提问开始。

**三个入口的切点行为**：

| 入口 | 切点行为 |
|---|---|
| 自动阈值压缩 | 保留最近 ~20k（上述逻辑） |
| 溢出压缩 | 同样保留最近 ~20k |
| 手动 `/compact` | 不选切点，压缩全部 active context |

两个边界 guard：切点落在 index 0 且是 user（退化情形）→ 找第二条 user 提问做切点，找不到就不压缩；压缩后生成的摘要消息插在保留区之前，作为新对话起点。

### 3. 生成摘要

- 用一个独立的模型请求做摘要（不用主对话的模型消息）。
- 要求输出固定结构：`Goal / Constraints / Progress / Key Decisions / Next Steps / Critical Context`。
- 如果之前已经压缩过（第一条是旧摘要），则让模型做"增量更新"而不是重新写。

### 4. 写入会话树

追加一条 `CompactionEntry`，记录 `summary` 和被替换的消息 id 列表。它是会话历史里的一个普通节点，所以之后依然可以查看/回退完整历史。

### 5. 重建 active context

从会话文件重放：被替换的旧消息换成那条摘要消息，加上保留的最近消息，作为新的"发给模型的消息列表"。

## 关键文件

```text
src/tau_coding/session.py      触发、压缩范围、生成摘要、落地（主逻辑）
src/tau_coding/context_window.py  token 估算与阈值
src/tau_agent/session/memory.py  重放时应用压缩，重建 active context
src/tau_agent/session/entries.py  CompactionEntry 定义
src/tau_coding/commands.py       /compact 命令
```

## 为什么这样设计

- **历史不丢**：压缩只是"读旧消息 → 写摘要"，会话文件完整保留，随时可回退。
- **简单可靠**：token 估算用字符数近似（4 字符 ≈ 1 token），不依赖各家 tokenizer。
- **自动压缩出错也不打断对话**：压缩失败只记日志，正常继续当前轮。
